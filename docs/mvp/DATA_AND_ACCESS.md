# Данные и права

## Реализованные сущности M0

| Сущность | Ключевые поля и ограничения |
| --- | --- |
| app_private.principals | Собственный UUID продукта, active; нет пользовательского доступа к таблице |
| app_private.auth_identities | provider + subject_id → principal_id; в M0 провайдер supabase, нет внешнего ключа на auth.users |
| agencies | UUID, название, создатель-принципал, серверное время |
| memberships | Составной ключ agency_id + principal_id, owner/manager, active |
| proposals | UUID, agency_id, создатель, title, JSON-документ, revision, серверные даты |

В M0 один принципал может создать одно агентство. Это временное ограничение первичного подключения, не фундаментальное правило SaaS. Приглашения, смена владельца и второе создаваемое агентство требуют отдельной миграции и операций; клиент не может вставить себе участие напрямую.

Создание агентства и первого владельца происходит в одной транзакции под блокировкой первичного подключения. Сбой участия откатывает и агентство, и новое сопоставление личности. Отозванное участие и inactive principal проверяются по текущему состоянию БД. Повторный вход не должен реактивировать заблокированного пользователя продукта.

## Матрица M0

| Операция | Без сессии | Чужое агентство / отозванный участник | Действующий manager | Действующий owner |
| --- | --- | --- | --- | --- |
| Читать агентство и его КП | Нет | Нет | Да | Да |
| Создать КП | Нет | Нет | Да | Да |
| Сохранить черновик с актуальной ревизией | Нет | Нет | Да | Да |
| Записать таблицу напрямую | Нет | Нет | Нет | Нет |
| Изменить участников/роль/владельца | Нет | Нет | Нет | Нет, операция ещё отсутствует |
| Опубликовать или открыть клиентскую ссылку | Нет | Нет | Не реализовано | Не реализовано |

Первичное создание агентства доступно проверенному пользователю без существующего участия; роль владельца сервер выводит из субъекта. Все отсутствующие возможности закрыты, а не разрешены по умолчанию. Существующие RLS-политики относятся только к сотрудникам, их нельзя переносить на клиентские варианты.

## Документ M0

schemaVersion = 1, до 64 блоков. Сейчас поддержаны только text и estimate. У блока UUID, тип, заголовок и visible; у text — body, у estimate — до 200 строк. Неизвестные поля, повторяющиеся ID блока и строки, некорректные типы и числа отвергаются. Пустое содержание допустимо для рабочего черновика.

В estimate строка содержит описание, quantityThousandths, unitPriceMinor, included и необязательные unitCostMinor/internalNote. Количество — тысячные доли единицы, цена — копейки; null обозначает неизвестное. Ноль цены известен и допустим. Формат, ограничения и явное округление — [ADR 0003](../adr/0003-releases-and-money.md).

visible управляет показом раздела. included управляет включением услуги в сумму. Эти признаки не взаимозаменяемы. Клиентская проекция отдельно перечисляет допустимые поля на каждом уровне; внутренние себестоимости и заметки не попадают в неё.

## Следующие сущности — ещё не созданы

| Сущность | Граница ответственности |
| --- | --- |
| brand_versions | Снимки токенов и логического логотипа; смена бренда не меняет старый выпуск |
| assets / asset_versions | Агентство-владелец, готовность, размер/хеш, приватный ключ объекта, права использования |
| venues / room_versions | Реальное место отдельно от неизменяемой геометрии и доказательств замеров |
| layouts / layout_versions | Ссылка на точную версию зала и библиотеку предметов, единый документ сцены |
| releases | Неизменяемый клиентский снимок, исходная ревизия, пины бренда/сцен/ресурсов |
| access_grants | Область чтения и действий, срок, отзыв, хеш секрета; без хранения токена в открытом виде |
| client_actors / variants | Отдельный проверяемый участник клиента и его личный вариант, базовый выпуск |
| submissions | Неизменяемое отправленное пожелание; изменение варианта его не переписывает |
| decisions / acknowledgements | Кто и что принял, к какому выпуску/области относится решение |
| entitlements / billing_events | Доступные возможности и история оснований; не выводятся только из состояния оплаты в браузере |
| audit_events | Важные действия и изменение доступа без полного текста КП и токенов |

У будущих дочерних сущностей ссылки внутри агентства должны проверять пару agency_id + resource_id. Одного UUID недостаточно для вложения чужого файла или сцены. Предоставление зала другому агентству — отдельное разрешение на ресурс; оно не даёт доступа к предложениям владельца.

## Самая важная граница клиента

Менеджер видит отправленное пожелание, но не личный неотправленный вариант заказчика. Это требует отдельных политик по автору и grant, а не только tenant RLS. Получатель не выбирает author_id в теле запроса. Общее разрешение «можно смотреть КП» не даёт доступа к черновику, исходным файлам, внутренней цене и управлению агентством.

Отзыв ссылки блокирует новые чтения/записи и повтор операции; уже полученные байты невозможно гарантированно забрать с устройства. Ссылки на файлы короткоживущие, выдаются после проверки доступа; конкретное время жизни выбирается до M2. Восстановление копии данных не должно восстанавливать ранее отозванный доступ.

## Владелец платформы

owner агентства не является оператором SaaS. Администрирование агентств, ограничений и тарифов потребует отдельного операторского допуска с MFA, серверными операциями и аудитом. Такой маршрут в M0 отсутствует. Поддержка не должна получать постоянное право читать все сметы; доступ к содержанию выдаётся отдельно по необходимости и фиксируется. Ручное назначение пилотной подписки не означает добавление административного ключа в браузер или обычный BFF-запрос.
