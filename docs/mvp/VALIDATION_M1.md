# Проверки начального среза M1

7 ноября 2026, Asia/Omsk. Только синтетические материалы. Это дополнение к [проверкам M0](VALIDATION.md); весь M1 и коммерческий пилот ещё не готовы.

## Что изменилось

Написаны серверные маршруты sign-in/sign-out/session и интерфейсы входа, первого агентства, списка/поиска/курсора и редактора текста/расчёта. Сессия проверяется сервером, токены не возвращаются в JSON, административный ключ не используется. Повтор создания с тем же ключом не дублирует КП. Поиск буквальный, включая *, % и _.

Редактор использует одну очередь записи с ревизиями: набор текста во время запроса не считается сохранённым его старым подтверждением. Потерянный ответ оставляет результат неопределённым; повтор не подставляет новую ревизию сам. При 409 автосохранение останавливается, правки остаются в памяти, доступны выгрузка и открытие актуального документа с предупреждением браузера. Секретные черновики автоматически не записываются в localStorage.

## Локальные результаты

| Проверка | Результат и границы |
| --- | --- |
| Typecheck | Успешно |
| npm test | 38 pass: 9 core, 15 web и 13 SQL-сценариев + родительская SQL-группа |
| Production build | Успешно; страницы входа/кабинета/редактора и все API компилируются |
| Standalone smoke | Health и девять закрытых API-операций; без конфигурации 503, приватное кеширование, /.env.local 404 |
| Домен/SQL | Повтор создания возвращает тот же ID и последующие правки; новый payload под прежним ключом отклоняется; чужое агентство не получает доступ; буквальный поиск проверен в PostgreSQL |
| Очередь сохранения | 6 тестов: набор во время запроса, конфликт, явный повтор, неверный ACK, B→A во время pending, потерянный ACK после commit |
| Числовой ввод | Копейки/тысячные из десятичной строки; ноль и неизвестное различаются; лишняя точность и переполнение отвергаются |
| Браузер | Изолированный реальный компонент редактора: ввод текста/цены, пересчёт, неверная цена, восстановление, успешный ACK и 409; телефон 390 px без горизонтального переполнения. Настоящая страница входа без Supabase показывает понятный отказ и не имитирует успех |

Для визуального прохода использовалась локальная тестовая оболочка вне продукта с имитацией ответов API. Она не является авторизацией, не включена в маршруты Next и не доказывает сетевой цикл Supabase. Снимки и оболочка находятся в игнорируемой .local/qa-m1; в публичном Git нет учётных данных.

## Независимый разбор

Найдены и исправлены две ошибки: ложное «Сохранено» после потерянного ответа и возврата к прежнему тексту; wildcard-поведение * у PostgREST ilike. Для первого добавлены регрессии pending/uncertain, для второго поиск перенесён в параметризованный SQL strpos с SECURITY INVOKER и RLS. Повторные проверки проходят.

## Непроверенные границы

Полного настоящего Auth/PostgREST нет: Docker Desktop не завершил запуск, advisors получил ECONNREFUSED. Владелец выбрал отдельную облачную организацию и отложил её подключение. Существующие проекты не изменялись, ресурсы и расходы не создавались.

После подключения отдельного синтетического стенда обязательно проверить настоящие cookies/refresh/logout, 401/403, двух сотрудников разных агентств, две конкурентные транзакции, реальные фильтры RPC/курсор, advisors, отрицательные тесты Data API и повторное открытие документа после входа. Приглашения/отзыв участников, собственные rate limits и аудит остаются задачами M1; выпуск, клиентские варианты и файлы ещё не реализованы.
