# Подключение синтетического стенда

Состояние на 13 ноября 2026. Это настройка стенда, не разрешение использовать реальные клиентские материалы или объявление production готовым.

## Supabase

Владелец создал отдельный проект и разрешил подключение. Перед применением миграций проверены точный host/пользователь из Session pooler и отсутствие прикладных таблиц. CLI применил пять миграций из репозитория с историей версий. Затем проверены семь таблиц с RLS, отсутствие табличных grants anon, реальные отказы чтения public-таблиц и create_agency без сессии через Data API. CLI advisors на уровне warn не показал проблем.

Соединение настройки с pooler использует TLS с проверкой CA и hostname. Результат `pg_stat_ssl` за pooler описывает другой участок соединения и не заменяет проверку клиентского сокета. Подтверждены `authorized=true`, `encrypted=true`, TLSv1.3 на клиенте настройки. Пароль БД нужен только для миграций/проверок; runtime приложения его не использует.

Локальная конфигурация находится в игнорируемом `apps/web/.env.local`. Обычные запросы приложения используют существующий серверный SSR-клиент с publishable key и правами пользователя. Код примера из мастера Supabase не заменял защищённый API и не добавлял service_role. SDK уже были установлены и закреплены; повторная установка не нужна.

Пока проверены Auth health и отказы API без сессии. Владелец сообщил, что создал пользователя в Authentication → Users; положительный вход ещё не наблюдался. Вход/refresh/logout, два агентства через Data API, две конкурентные транзакции и восстановление не объявлены пройденными. Текущие Auth settings разрешают signup; закрытый режим пилота ещё следует настроить. Отсутствие signup-кнопки в приложении само по себе этого не обеспечивает.

## Vercel

Владелец импортировал репозиторий. Найденный деплой был собран из раннего `main` с документацией, без Next.js framework; страница отвечала 404. Проект настроен на:

- Framework: Next.js.
- Root Directory: `apps/web`.
- Node.js: `24.x`.
- Source files outside root: включены для `packages/core` и workspace lockfile.
- Стандартные install/build/output команды Next.js, без фиктивного статического output.

Настройки сами не заменяют исходный код старого деплоя. Новый выпуск не выполнен; актуальная реализация остаётся в отдельной рабочей ветке до review. Условия использования Hobby и коммерческий production-провайдер не считаются утверждёнными созданием проекта.

Для production environment нужны три серверные переменные: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `APP_ORIGIN`. Последняя — точный origin выбранного адреса кабинета без завершающего слеша. Добавление env через интеграцию отклонено Vercel с 403; CLI с отдельной авторизацией в окружении не установлен. Локальный файл импорта подготовлен в `.local/vercel-production.env` и не входит в Git. В нём нет пароля БД. Для preview нужен собственный точный `APP_ORIGIN`; значение production нельзя автоматически переносить на произвольный preview-адрес.

После env и review исходного кода проверить сборку, настоящий `/login`, 401 без сессии, вход, создание агентства/КП, сохранение, повторное открытие и выход. Наличие статуса Ready у старой сборки этого не доказывает.
