# Поэтапная реализация

Этапы идут по доказательствам готовности, а не по календарным обещаниям. Каждый этап оставляет работающий проверяемый срез. Бюджет, платные ресурсы, тарифные обещания и существенное расширение продукта обсуждаются до заказа/реализации.

## M0 — серверное основание

Реализовано: отдельное Next-приложение, чистый core, схема агентств/участников/черновиков, собственная идентичность продукта, защищённые SQL-операции, API чтения/создания/сохранения, запрет устаревшей записи, расчёт в копейках и клиентская проекция. Разработка и тесты не требуют облачного проекта. Прототип сохранён отдельно.

Критерии локального среза: typecheck, core/HTTP/SQL проверки и production-сборка проходят; обычная роль не читает чужое агентство и не повышает права; ошибка первого owner откатывает всё создание; два последовательных запроса с одной ревизией дают один успех; неизвестная сумма не равна нулю; внутренние поля отсутствуют в снимке.

Оставшийся интеграционный gate M0: реальный локальный/синтетический Supabase Auth + PostgREST, advisors и два независимых соединения. PGlite эту границу не покрывает. До её прохождения не подключаем настоящие данные. Результаты текущих проверок фиксируются в [журнале](VALIDATION.md).

## M1 — настоящий кабинет и приватный редактор

Реализовать вход/выход и восстановление сессии, закрытое подключение двух агентств, приглашение/отзыв менеджера. Обеспечить последнего владельца и сериализацию конфликтующих операций с составом команды. Перенести утверждённые взаимодействия прототипа в новый кабинет: список, создание без анкеты, текст/расчёт, порядок/скрытие разделов, автосохранение и конфликт. Дальше добавить остальные блоки, бренд-токены и проверенные изображения.

Готово, когда два агентства проходят реальный browser → API → Data API → БД → повторный вход и не видят друг друга; редактор не сообщает о сохранении до ответа; потеря ответа не дублирует создание (ключ операции); истёкшая сессия и 409 не уничтожают введённое; есть курсор списка и безопасный журнал запросов. Файлы приватны и проходят проверку. Работа не требует настройки кода под новое агентство.

## M2 — выпуск и клиентское взаимодействие

Добавить версии бренда/ресурсов, атомарный выпуск и управляемые grants. Выбрать проверяемую идентичность автора клиентских действий, не усложняя чтение. Реализовать вопрос, разрешённый выбор, личный вариант, отправленный снимок, разбор менеджером и новый выпуск. Операции отправки/выпуска идемпотентны.

Готово, когда изменение внутренней цены/бренда не меняет старое издание; личный неотправленный вариант не читает даже менеджер; два получателя не получают один общий черновик; чужой/отозванный/истёкший grant не даёт прочитать или изменить данные, включая повтор запроса; перенос пожелания не публикует документ автоматически; подтверждение привязано к конкретному выпуску. В DOM, JSON и файлах клиентской страницы нет внутренних данных. Телефон проходит чтение/вопрос без WebGL.

## M3 — реальная площадка

Подготовить один зал по [протоколу](SPATIAL_PILOT.md), хранить версии помещения и предметов, перенести пространственный модуль на общий проверяемый формат. Инструменты: перенос, поворот, возврат на полку, Undo, ограниченные размеры зон, сохранение личного варианта/миниатюры, план/объём/прогулка.

Готово, когда физические контрольные замеры и ограничения записаны; все виды совпадают после открытия из БД; коллизии и посадка проходят сценарии пилота; опубликованная сцена воспроизводима после изменения библиотеки; запрещённые ссылки на ресурсы отклоняются сервером; измерены загрузка/управление на обычных устройствах. Работает также КП вообще без площадки.

## M4 — коммерческий закрытый пилот

Выбрать и развернуть российский контур, повторить миграцию/восстановление на синтетике, проверить экспорт и удаление, добавить мониторинг/оповещения/резервирование/ротацию ключей. Определить один пилотный пакет, правила trial/отмены/ссылок/архива, ручное назначение возможностей с аудитом и сроки хранения. Автоплатежи зависят от отдельного выбора провайдера.

Готово, когда восстановление в чистой среде измерено; отрицательные тесты Auth/RLS/Storage/клиента проходят в фактической инфраструктуре; нагрузочный профиль двух агентств измерен; нет известных критических проблем; оба агентства и получатели самостоятельно выполняют основные задания; опубликованные условия соответствуют поведению сервиса. Только затем используем настоящие персональные и коммерческие данные в пилоте.

## После подтверждения ценности

Самостоятельный конструктор геометрии, кабинет площадки, общая библиотека с происхождением/модерацией, собственные домены, автоподписка, расширенные роли, импорт и совместное редактирование ранжируются по наблюдаемой частоте/пользе. Не откладываем безопасность до роста, но и не строим всю экосистему каталога до первого доказанного платного цикла.
