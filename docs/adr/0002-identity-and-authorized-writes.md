# ADR 0002: идентичность продукта и проверяемые записи

Дата: 6 ноября 2026. Статус: реализовано в начальной миграции; сетевой Auth/PostgREST gate ещё не пройден.

Задача: изолировать агентства, исключить самоназначение владельца и потерю параллельных изменений, сохранить возможность смены Auth-провайдера.

Решение: собственный principal UUID и закрытое сопоставление provider/subject. Роль — действующее участие в агентстве; email и user metadata не доказывают доступ. При первичном создании роль owner выводится из проверенного субъекта и записывается атомарно вместе с агентством. Идентификатор автора никогда не принимается из тела операции.

Таблицы public доступны пользователю только для SELECT через RLS. Записи выполняют узкие SECURITY DEFINER-функции в app_private с пустым search_path, полными именами объектов и явной проверкой текущего субъекта/агентства. EXECUTE у PUBLIC/anon отозван. В public только SECURITY INVOKER-обёртки; app_private не включается в API schemas. Разрешённый пользователь может вызвать обёртку напрямую через Data API, поэтому все предметные проверки повторяются в SQL.

Привилегированный владелец функции технически обходит RLS: поэтому наличие RLS само по себе не доказывает безопасность операции. FORCE RLS здесь не включён; этот выбор нужен для закрытых helper-функций и проверяется тестами от имени обычной роли. Ни привилегированная сессия, ни service_role не используются сервером для повседневной работы. [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [функции БД](https://supabase.com/docs/guides/database/functions).

Сохранение блокирует только доступную пользователю строку и сравнивает expected_revision. При несовпадении возвращает EC409, не выполняя UPDATE. CAS обеспечивает защиту от незаметного затирания, но не синхронное совместное редактирование. Отдельный тест двумя соединениями обязателен перед пилотом.

Альтернативы: прямой UPDATE с клиентской дисциплиной ревизии слабее серверной обязательной операции; административный BFF без caller-scoped запросов увеличивает цену ошибки авторизации; auth.users как FK всего домена усложняет смену провайдера. Компромисс — немного дублирования проверок HTTP и SQL ради защиты прямого Data API.

Ограничение M0: один созданный workspace на principal, нет API управления участниками. Будущий перенос/удаление последнего owner требует сериализуемой операции на агентстве и отдельных тестов гонки. Этот ADR не разрешает произвольно расширять SECURITY DEFINER-функции.
