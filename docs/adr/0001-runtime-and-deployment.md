# ADR 0001: модульный сервер и независимое размещение

Дата: 6 ноября 2026. Статус: выбран для реализации M0; production-провайдер не выбран.

Задача: начать безопасный SaaS после учебного Vite-прототипа, без облачного счёта в разработке и с возможностью российского размещения. Прототип использует localStorage и не является основанием доверенной многопользовательской системы.

Решение: Next.js/TypeScript для нового сервера и будущего кабинета, чистый packages/core, PostgreSQL с явными SQL-миграциями, Supabase как первый Auth/Data API адаптер. Старый прототип остаётся отдельным приложением. Объектное хранилище и обработка файлов добавляются за узкими интерфейсами. Начинаем одним сервисом, без микросервисного деления и обязательных фоновых платформ.

Альтернативы: сохранить Vite + отдельный API — допустимо, но добавляет второй runtime-договор на текущем этапе; привязаться к одному BaaS во всех доменных модулях — быстрее сначала, сложнее перенос; писать собственную аутентификацию — лишняя ответственность без потребности. Next поддерживает Node/Docker вне Vercel. [Self-hosting](https://nextjs.org/docs/app/guides/self-hosting).

Последствия: серверный SDK изолирован от домена; нет административного ключа в обычном запросе. Миграция требует адаптации Auth/Data API, файлов и эксплуатации, а не только строки соединения. Бесплатная разработка локальная; Supabase Free — возможный стенд на синтетике. Коммерческий продукт не разворачивается автоматически на Vercel Hobby. [Условия Hobby](https://vercel.com/docs/plans/hobby).

Пересмотр: если интеграционный тест или операционная стоимость первого российского контура показывает, что отдельный PostgreSQL/Auth проще, заменяем адаптер до реальных данных, сохраняя правила core и тесты доступа.
