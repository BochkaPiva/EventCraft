# Библиотека площадок и единый сценарий добавления

5 ноября 2026 года. Статус: рекомендация для обсуждения. Экраны не реализованы; состав MVP не утверждён.

## Уточнение владельца

Желаемое долгосрочное направление — поддержать несколько способов получения макета: создание менеджером, подготовка представителем площадки и помощь команды продукта. Представителям площадок со временем может быть интересна дополнительная видимость среди агентств; на старте наличие аудитории нельзя обещать.

Приоритет интерфейса: обычный менеджер без технических навыков должен понимать следующий шаг; простые названия, предсказуемые действия, один-два уровня навигации. Это не требует помещать все поля на один экран: последовательный процесс с видимым прогрессом может быть проще большой формы.

## Предлагаемый выбор по библиотеке

Рекомендация — включить библиотеку в продукт как средство находить и повторно использовать доступные залы. Первая версия может объединять личные и предоставленные общие модели в одном разделе. Открытая площадка с массовой самостоятельной публикацией, рейтингами и широким географическим покрытием — отдельный объём развития.

При просмотре библиотеки пользователь видит только разрешённые ему помещения. Личный зал другого агентства не попадает в поиск. Режим доступа и степень проверки геометрии — разные свойства.

## Один раздел и прямой выбор зала

Основной вход: «Площадки». Поиск по названию или адресу, выбранный город и простой переключатель доступных/своих помещений. Город и район — фильтры списка; не требуется проходить цепочку город → район → заведение → этаж → зал.

Результат поиска ведёт сразу к конкретному залу: «Ресторан „Берег“ — Большой зал». В данных заведение и помещение остаются разными сущностями; интерфейс не заставляет проходить отдельную страницу для каждой из них.

В списке достаточно фотографии/превью, названия зала, адреса и краткой информации об основании размеров. При открытии доступны план, 3D, существенные ограничения и действие «Использовать в КП». Подробности проверки раскрываются отдельно. Заявленная площадкой вместимость не выдаётся за рассчитанную посадку конкретного мероприятия.

Если подходящего зала нет, действие «Добавить зал» открывает один процесс создания. До создания нового предлагаются вероятные совпадения, чтобы не плодить дубликаты. Совпадение названия не приводит к автоматическому объединению.

## Два начала одного процесса

Первый вопрос: «У вас есть план помещения?»

- «Загрузить план» — приложить существующее изображение/документ, выбрать нужный зал, указать известный размер и проверить масштаб. В первом варианте это может быть подложка и ручная подготовка; загрузка файла не означает автоматического распознавания.
- «Начать с формы» — выбрать простой контур и ввести внутренние размеры по показанным стрелкам. Результат сразу виден на схеме.

Дальнейшие шаги общие: добавить входы, колонны и неподвижные объекты; проверить полученный зал; сохранить черновик. Основные размеры нужны для работоспособного плана, высоты — для соответствующего 3D. Неизвестные сведения можно оставить для уточнения с явным состоянием готовности.

Фотографии прикладываются как помощь, а не как отдельный обязательный путь моделирования. Для простого помещения не показываются инструменты сложной геометрии. Параметры двери или колонны появляются после её выбора рядом с планом, без многоуровневых меню.

«Попросить площадку заполнить» — дополнительное действие того же черновика, доступное на нужном шаге. Представитель получает ограниченное приглашение к конкретному залу и недостающим полям, а не доступ к кабинету агентства. Приглашение отправляет пользователь явно. «Нужна помощь» передаёт подготовку той же модели команде продукта при согласованных условиях услуги.

Один формат данных и общий редактор не означают одинаковые полномочия. Вклад приглашённого участника сохраняется в черновике; изменения опубликованной версии и рабочего КП не применяются незаметно. Должны быть видны автор, изменённые данные и действия по принятию исправлений.

## Завершение и публикация

Основное действие после заполнения — «Сохранить зал». По умолчанию он остаётся личным для организации. Неполный черновик доступен для продолжения, но не получает ложного статуса точного плана.

«Предложить в общую библиотеку» — отдельное второстепенное действие после сохранения. Оно требует разрешений на материалы и проверки версии. Сохранение зала, публикация КП и предложение зала другим агентствам не объединяются в одну кнопку.

Общедоступная версия не раскрывает клиентские расстановки, сметы, комментарии и проверочные вложения. Личный макет может использоваться в собственном КП по согласованным правилам готовности; это не делает его общим.

## Проверка и обратная связь

Голоса «всё правильно» могут быть сигналом опыта использования, но не доказательством размеров. Популярная модель тоже может иметь неверную ширину. Не вводить минимальное число голосов как автоматическое условие точности или публикации.

Показывать узкие понятные основания, например «Размеры указал автор», «Сверено с планом площадки», «Есть контрольные замеры». Формулировка должна соответствовать фактическому охвату проверки; сведения о дате, проверенных элементах и оставшихся вопросах доступны по действию «О размерах». Подтверждение представителя площадки не подменяет проверку геометрии.

В доступной модели есть действие «Нашли неточность?». Пользователь отмечает объект или сторону, описывает проблему и при наличии прикладывает источник. Сообщение поступает на разбор; оно не меняет чужую геометрию автоматически и не позволяет несколькими жалобами незаметно уничтожить опубликованную версию.

При подтверждённой существенной ошибке нужны текущий статус проблемы, уведомление использующих модель организаций и исправленная версия. Старые КП не перестраиваются молча. Новые использования проблемной версии ограничиваются соразмерно риску.

## Граница предложения для первого выпуска

Рекомендуемый ограниченный вариант для оценки трудоёмкости:

1. Единый список доступных залов и поиск по названию/городу.
2. Один редактор простого одноуровневого помещения.
3. Ввод по форме и прикрепление готового плана как два входа в тот же редактор.
4. Адресное приглашение представителя к черновику вместо отдельного большого кабинета площадки.
5. Личный доступ по умолчанию и ручной разбор предложений в общую библиотеку.
6. Понятное происхождение размеров и сообщение о неточности.

Массовое самостоятельное подключение площадок, продвижение карточек, сложные рейтинги, произвольный CAD, автоматическое восстановление по фотографиям и сложное объединение конкурентных правок требуют отдельной оценки. Внесение всех входов в долгосрочную архитектуру не обязывает реализовать каждый из них до первого платного пилота.

## Как проверить простоту

Показать последовательность действий менеджерам пилотов на конкретном задании, без объяснения разработчика. Проверить поиск готового зала, создание простого нового зала, передачу недостающих размеров представителю и различие между личным сохранением и общим доступом.

Наблюдать завершение заданий, возвраты назад, ошибочные публикации, вопросы о названиях и местах, где приходится вмешиваться. Если два уровня меню достигнуты ценой перегруженного экрана, требование простоты не выполнено. Численные критерии устанавливаются по исходному наблюдению до приёмочного теста, а не объявляются достигнутыми заранее.
