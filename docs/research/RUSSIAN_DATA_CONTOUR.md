# Российский контур данных: проверка и варианты

5 ноября 2026 года. Статус: исследовательская записка. Провайдер, конфигурация и юридические документы не выбраны. Материал не является заключением о соответствии ещё не созданного приложения законодательству.

## Что подтверждено источниками

Федеральный закон № 23-ФЗ от 28.02.2025 изменил ч. 5 ст. 18 закона № 152-ФЗ: при сборе персональных данных граждан РФ перечисленные операции с использованием баз за пределами России не допускаются, за предусмотренными нормой исключениями. Изменение охватывает запись, систематизацию, накопление, хранение, уточнение и извлечение. [Официальный текст изменения, статья 1](http://kremlin.ru/acts/bank/51683).

Закон вступил в силу 1 июля 2025 года. [Официальный текст, статья 10](http://kremlin.ru/acts/bank/51683/page/2).

Локализация при сборе и последующая трансграничная передача — разные вопросы. Нельзя делать вывод ни о допустимости любой передачи после записи в РФ, ни о запрете любого иностранного сервиса. Порядок трансграничной передачи и применимые исключения требуют отдельной проверки по фактическим потокам.

РКН публикует отдельные страницы [трансграничной передачи](https://pd.rkn.gov.ru/cross-border-transmission/) и [уведомления об обработке](https://pd.rkn.gov.ru/operators-registry/notification/). Ограничение текущей проверки: прямое чтение этих страниц и одного регионального текста закона завершилось тайм-аутами; доступны официальные поисковые выдержки. Поэтому сроки уведомлений, страны и исчерпывающий перечень исключений здесь не утверждаются. Перед запуском требуется сверить полную действующую редакцию и применимость процедур к нашему продукту.

## Какие данные защищаем

Сумма сметы и пустой план зала сами по себе не обязательно являются персональными данными. Они могут быть конфиденциальными коммерческими сведениями. ФИО, контакты сотрудников и клиентов, учётные записи и авторство комментариев требуют отдельного учёта как данных о людях. Фотографии, сетевые идентификаторы и телеметрия оцениваются в контексте возможности идентификации.

По некоторым потокам платформа может сама определять цели обработки, по клиентским данным — работать по поручению агентства. Роли и обязанности нужно установить в договорах и реестре потоков, а не назначать одним общим утверждением для всех данных.

Размещение у провайдера, заявляющего поддержку 152-ФЗ, не делает автоматически соответствующими интерфейс, доступ сотрудников, внешнюю аналитику и договоры платформы.

## Инженерная рекомендация для обсуждения

Размещать российский рабочий контур целиком в РФ: API и серверное отображение приватных КП, авторизацию, PostgreSQL, приватные файлы, резервные копии, обработку загрузок, журналы, аудит и используемые для этих данных почтовые сервисы. Это проектная рекомендация для снижения риска и сложности, а не буквальное утверждение, что закон без исключений запрещает любой зарубежный компонент.

Российская база за зарубежным API не исключает получения зарубежным сервером персональных данных, содержимого КП и cookies. Поэтому предположение «хостинг может быть любым, достаточно базы в РФ» для проекта не принимается без проверки фактического маршрута.

Отдельно проверяются CDN, reverse proxy, WAF, error tracking, аналитика, шрифты и виджеты. Сам факт прохождения зашифрованного трафика через сеть не следует автоматически приравнивать к хранению в зарубежной базе; нужны сведения о получателях и выполняемой обработке.

Для экспериментов в облачном Supabase предлагаются только синтетические данные и отдельные секреты. Реальные КП, контакты, снимки с людьми, документы и копии production не переносятся туда ради удобства тестирования. Self-hosted Supabase на инфраструктуре РФ — отдельная техническая гипотеза: эксплуатация, обновления и бэкапы остаются задачей команды.

## Кандидаты для технического сравнения

| Кандидат | Официально описанные возможности | Что выяснить до выбора |
| --- | --- | --- |
| Yandex Cloud | Managed PostgreSQL, Object Storage, резервные копии и PITR; есть материалы по 152-ФЗ | Фактический регион каждого сервиса и копий, топология HA, текущая доступность зон, экспорт и цена |
| Selectel | Managed PostgreSQL, приватная сеть, реплики, S3 и восстановление по журналу | Локации, независимый бэкап и восстановление; встроенные бэкапы не заменяют переносимый экспорт |
| Timeweb Cloud | Managed PostgreSQL, приватные адреса, реплики, бэкапы и S3 | Явный выбор РФ: PostgreSQL предлагается также за пределами РФ; размещение копий, платные дополнения и HA |

Проверенные материалы поставщиков:

- Yandex Cloud: [копии PostgreSQL](https://yandex.cloud/ru/docs/managed-postgresql/concepts/backup), [регионы](https://yandex.cloud/ru/docs/overview/concepts/region), [материалы по 152-ФЗ](https://yandex.cloud/ru/solutions/152-fz).
- Selectel: [PostgreSQL](https://selectel.ru/blog/tutorials/how-postgresql-cloud-databases-work-in-selectel/), [резервные копии](https://docs.selectel.ru/managed-databases/postgresql/backups/), [объектное хранилище](https://selectel.ru/services/cloud/storage/).
- Timeweb Cloud: [PostgreSQL](https://timeweb.cloud/services/postgresql), [S3](https://timeweb.cloud/services/s3).

Наличие реплики не заменяет резервную копию. Встроенные бэкапы Selectel не выгружаются как переносимый файл согласно инструкции; отдельный экспорт и проверка восстановления нужны независимо от наличия PITR.

Численная стоимость пока не сравнивается: нужны одинаковые CPU/RAM, диск, реплики, объём файлов/трафика, срок хранения копий, дополнительные сервисы и НДС. Прежняя оценка Vercel/Supabase не является бюджетом российского production.

## Начальный реестр рисков безопасности

| Риск | Что предстоит проверить в реализации |
| --- | --- |
| Доступ к чужому проекту по ID | Авторизация каждого запроса, членство организации, ограничения связей БД, тесты отрицательного доступа |
| Раскрытие маржи в клиентском КП | Отдельная схема выдачи с разрешёнными полями; внутренние цены не отправляются в браузер |
| Утечка через общую площадку | Раздельные публикации геометрии и КП, отдельные права на ресурсы и проверочные документы |
| Перебор или утечка ссылки | Непредсказуемый токен, хеш на сервере, отзыв/срок, ограниченная сессия, очистка логов и referer |
| Публичное кеширование приватного КП | Проверка заголовков, ключей кеша, CDN и авторизации на пути выдачи |
| Опасный файл/внешний URL | Проверка реального формата, лимиты, безопасная обработка в изоляции; импорт URL не даёт доступа во внутреннюю сеть |
| Слишком широкие полномочия | Отдельные административные роли, аудит, минимальный доступ поддержки и MFA для привилегированных пользователей |
| Потеря/порча данных | БД и файлы копируются отдельно, ключи восстановления доступны, учебное восстановление выполнено |
| Утечка через внешнюю интеграцию | Реестр получателей и мест обработки, фильтрация логов, синтетические тестовые данные |

Это исходные вопросы проектирования, не свидетельство того, что меры уже реализованы. До подключения реальных агентств нужны модель угроз, матрица доступа, проверка восстановления и разбор фактических потоков с учётом действующих требований.
