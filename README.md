# EventCraft

Платформа интерактивных коммерческих предложений для ивент-агентств: персональные страницы, фирменное оформление, точные расстановки и просмотр площадки в 3D.

EventCraft — рабочее название. Самостоятельный бренд продукта определяется отдельно.

## Статус

Подготовлен [работающий локальный прототип](prototype/README.md): от первого входа и создания КП до расстановки, 3D-прогулки, клиентских пожеланий и нового выпуска. Для проверки используются только демонстрационные данные.

Начата [серверная реализация MVP](docs/mvp/README.md): Next.js, доменный модуль, PostgreSQL с изоляцией агентств и API приватных черновиков. Написаны cookie-вход, кабинет со списком/поиском и редактор текста/расчёта с автосохранением, защитой от конфликта и потери ответа. Полный проход через настоящий Supabase Auth/PostgREST ещё не проверен; отдельный облачный стенд отложен. Публикации, файлы, платежи и production-инфраструктура ещё не реализованы. Исследовательские предложения остаются гипотезами, если явно не обозначены как требования.

Проверки и исправления интерфейса фиксируются в [журнале прототипа](prototype/UX_REVIEW_LOG.md). Исследование и прототип не подтверждают готовность сервиса к коммерческой эксплуатации.

## Разработка MVP

Node.js 24.14.1, npm; команды выполняются из корня:

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run dev
```

Новое приложение: http://127.0.0.1:3000/login. Без настроенного Auth приватный API отвечает 503 и вход недоступен. /api/health проверяет только живость процесса. Для синтетического стенда скопировать apps/web/.env.example в apps/web/.env.local; значения брать только от своего тестового проекта. Не использовать административный ключ. Миграции сами не применяются в облаке. [Текущая проверка M1](docs/mvp/VALIDATION_M1.md).

SQL-тесты исполняют миграции в PGlite без Docker. Настоящие Supabase Auth/PostgREST, параллельные соединения, восстановление и Docker-образ требуют отдельных проверок; [результаты и ограничения](docs/mvp/VALIDATION.md). Dockerfile подготовлен для standalone Node-сервера; его запуск не проверен без Docker-демона.

Прототип запускается отдельно по [его инструкции](prototype/README.md); его localStorage и демонстрационный доступ не связаны с новой БД. CI проверяет приложения раздельно, без деплоя и облачных секретов.

## Принципы

- Данные агентств изолированы; предоставление доступа к площадкам и мебели требует явного разрешения.
- План, объёмный вид и прогулка используют одну модель расстановки.
- Клиентские варианты отделены от оригинала менеджера.
- Опубликованное предложение сохраняет конкретную версию контента, оформления и связанных ресурсов.
- Подключение агентства и создание КП не требуют изменения кода.
- КП можно готовить без выбранной площадки; набор разделов зависит от задачи, а не от обязательной банкетной структуры.
- Размещение мебели в редакторе не является бронированием.
